The gateway is configured entirely through environment variables — there is no
config file and no command-line flags on the server binary. It reads them once
at boot; changing one means restarting the process.

<Aside type="tip" title="Generated, not hand-written">
The table below is emitted by `make -C gateway docs` directly from the
gateway's config manifest (`gateway/internal/config/reference.go`). A CI check
(`make -C gateway check`) fails if the gateway starts reading a new variable
that isn't documented here, so this reference can't silently fall behind the
code.
</Aside>

The two `FARCASTER_OIDC_*` **required** variables have no default — the gateway
refuses to start without them (see [Install](/docs/install/) and
[Auth & multi-tenancy](/docs/concepts/auth-and-multi-tenancy/)). Everything
else has a safe default or a dev-only fallback; the [Deployment](/docs/self-hosting/deployment/),
[Postgres](/docs/self-hosting/postgres/), and [KMS & secrets](/docs/self-hosting/kms-and-secrets/)
pages cover the production-relevant ones in context.

<ConfigReference />

Secrets (`FARCASTER_DATABASE_URL`, `FARCASTER_KMS_KEY`, and any provider
credentials) should come from your platform's secret store or an injected
environment, never from a committed file — see
[KMS & secrets](/docs/self-hosting/kms-and-secrets/).
